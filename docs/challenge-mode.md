# 3分チャレンジ（Issue #45、手動B案）

「積む」の中で「通常」と「3分チャレンジ」を選ぶ。通常の最大5個のゲーム、採集したパーツ、ギャラリー、サーバには変更を加えない。

- 固定の5形状（棒・L・U・輪・ジグザグ）。長辺1m・通常の摩擦。丸い描画・角ばった当たり判定は共通の `StackWorld` を使う（#67・#71）。
- 各5問に全種類が1回ずつ出るシャッフルバッグ。`java.util.Random` の種とルール `manual-180-v2` を記録し、同じ種なら同じ順で再現する。形・摩擦・時間のルールを変えたらIDも変える。
- 手動で左右移動（0.1m）・回転（15度）し「置く」。自動落下するA案は含まない。
- 180秒の前景経過時間。単調時計を使い、物理の時間上限とは分離する。背景・別タブ・通常モードへ移った間は時計と物理を止める。画面回転ではViewModelが保持する。OSによるプロセス終了時の途中再開は対象外（確定済みの記録は残る）。
- 入力時にも時計を更新し、締切ちょうど以降の移動・回転・配置を拒否する。締切直前に置いたピースは対象、置く前のゴーストは対象外。
- 各配置後、落下したものを毎フレーム除去し、静止したら次へ進む。途中の待ち時間は前景時間6秒までとし、動き続けていても次のピースを操作できる（途中で3分ゲームを終了しない）。締切後は別途最大6秒待ち、静止しなければ未確定として終了する。浮いている塔をランキングに登録せず、締切後に静止した高さだけを固定する（#41の意図）。背景中はこの待ち時間も止まる。
- 結果はViewModelから端末内の専用JSONにAtomicFileで保存。確定した結果の保存は画面の離脱で取り消さない。run IDで重複を防ぎ、同じルールだけを高さ順に並べる。同値は同順位。書き込み失敗は表示して再試行でき、保存が済むまで次のゲームを始めない。破損したデータを空として上書きしない。

## 並行作業と統合条件

Issueの3段階（ルール・画面・保存）を今回の実装依頼に合わせ1本のPRにまとめた。**#41/#42/#43の完了を意味しない**。通常モードの `StackScreen` / `StackViewModel` / `StackViewport`、共通の物理、収集・選択画面は編集していない。入口の `AppNav` だけを `StackModes` に差し替えた。

- #62・#63・#70 はClaude側のレビュー・修正を優先し、このPRから更新しない。このチャレンジは専用の時計・静止判定・座標変換で動くため、これらを先行マージせずにレビューできる。通常モードとの統合順は各PRの担当者と合わせる。
- #43の共通操作ボタンは未統合。このモードは既存の `PressButton` 系で左右・回転を用意し、#43統合時に共通化する。#43全体（物差し等）の代替ではない。
- カメラは上下左右の範囲を配置の切替時と結果確定時だけ計算する。台の下の張り出しも含め、狙い・落下中は固定する。操作欄と情報欄の高さも状態によらず確保する。#70と同じ全体表示の方針で、#70統合後の変換・補間の共通化は別途調整する。
- #75・#77の収集/選択UI、#68のギャラリーには変更しない。ランキングは既存ギャラリーへ送らず、この端末内に閉じる。

## セルフレビューでの修正

- 途中の6秒タイムアウトを「次のピースへ」に修正し、3分間の物理シミュレーションで5個を超えて積み続けられることを検証した。ルール変更前の記録と混ざらないようv2とした。
- 最終静止待ちの上限を前景時間で測り、低FPSでいつまでも終わらない問題を修正した。
- 結果保存をCompositionからViewModelへ移動。画面なしでの保存、保存中の再挑戦防止、失敗時再試行、遅れて到着する初回読込が新記録を消さないことを検証した。
- 下や横への張り出しを縮尺に含め、情報・操作欄を固定して塔の表示位置が動かないようにした。大きな文字ではボタンを折り返す。
- 既存の他作業の端末・エミュレーターは操作していない。端末確認の未実施を自動テスト成功と混同しない。
