# 3分チャレンジ（Issue #45、手動の B 案）

決めたことの要約は `docs/decisions.md` の 58。ここは細かい決め方。

積むタブを開いたときの、遊び方を選ぶ画面（決定 60・`ui/game/ModeSelect.kt`）の「3 分チャレンジ」から始める。通常のモード（最大 5 個のゲーム）、記録したパーツ、「みんな」、サーバには手を入れない。

## 決まり（`core/.../challenge/ChallengeRun.kt`、ID `manual-180-v3`）

- 固定の 5 形状（棒・L・U・輪・ジグザグ）。長辺 1 m・ふつうの摩擦。丸い見た目と角ばった当たり判定は共通の `StackWorld`（#67・#71）
- 5 回に 1 回ずつ全部の形が出る袋。`java.util.Random` の種を記録し、同じ種なら同じ順番になる
- 左右 10 cm（±1.5 m まで）・回転 15° で狙って「置く」（通常のモードの ◀▶ は 5 cm。チャレンジは決まった大きさの形を速く積むので、刻みを大きくしている）。自動で落ちてくる A 案は入れない
- 時計はアプリが前に出ている間の 180 秒（単調時計。端末の時刻や物理の時間の上限とは別に数える）。裏・別のタブ・通常のモード・確かめの窓の間は、時計と物理を止める。画面の回転では ViewModel が持ち続ける。OS にアプリが止められたときの途中からの再開はしない（確定した記録は残る）
- 操作のときにも時計を進めて確かめ、00:00 ちょうど以降は動かせない。締切の直前に置いた形は数える
- 置いたあとは、落ちた形を毎コマ取り除き、止まったら（0.8 秒より後）次の形へ。**途中は 3 秒まで**しか待たず、揺れていても次の形を出す（v3。v2 は 6 秒）。揺れている途中に次の形へ進んだあと、狙っている間に塔が崩れて低くなったら、次の形が出てくる高さと `cameraTop` も崩れたあとの高さまで下げる（上げる向きには動かさない。#78 の A のレビュー）
- 締切のあとは最大 6 秒待ち、止まった塔の高さだけを記録にする。止まらなければ記録しない（浮いている高さは記録しない。#41 の考え方）
- 形・摩擦・時間の決まりを変えたら ID を上げる。記録には ID を必ず書き出す（既定値にすると保存で省かれ、読むと今の決まりに化けていたため）

## 画面（`ui/game/ChallengeScreen.kt`）

- 上の行：「‹ 戻る」（選ぶ画面へ）と「3 分チャレンジ」の札（`ModeSelect.kt` の `ModePlayPage` から `leading` で受け取る。通常のモードと同じ）。始める前の説明の画面でも同じ。はじめは白い紙のラベルの上の札で「通常」と切り替えていたが、選ぶ画面にまとめた
- 地は塗らない。ほかの画面と同じ方眼の紙と今の天気（決定 59）
- 上から「情報」「キャンバス」「操作」の 3 段（通常のモードと同じ形）
  - 情報：「残り 02:37」（`headlineSmall`。数字は等幅。残り 10 秒から赤）、右に「模型の高さ」と「次」の形
  - キャンバス：変換は通常のモードと同じ `StackViewport`（zoom は 1 のまま）。台はキャンバスの上から 78%（下のほう）。次の形が出てくる高さ＋どう回しても入る半径（`cameraTop`）が入るところまで、0.4 秒かけて視点を上げる（`StackViewport.follow`）。`cameraTop` は次の形に進むときと、狙っている間に塔が崩れて低くなったとき（0.05 m 以上）だけ変わるので、ふだん狙っている間と落下中はカメラが動かない。引かない
  - 操作：「◀ ⟲ 15° 置く ⟳ 15° ▶」を 1 行。その下に「やり直す」「中断」。操作の段は中身の高さだけ（上限は画面の 45%）で、1 回の中では縮めない
- 「やり直す」「中断」は確かめの窓を出す。どちらもその回は記録に残さない。中断ははじめの画面（説明と、この端末の記録）に戻る
- 落下中は、狙うときのボタンの行と同じ高さを「落下中…」で取っておき、「やり直す」「中断」を動かさない（エミュレータで続けて「置く」を押すと、「置く」があった場所に来た「中断」を押して確かめの窓が開いていた）
- 組み立て直しを減らす：`ChallengeFrame` は操作・次の形・結果のときだけ変わる。塔の図形（`shapes`）はキャンバスの描画の中だけで読み、残り時間（`remainingSeconds`）は秒が変わったときだけ変わる。前は毎コマ新しいフレームを作り、画面全体を毎コマ組み立て直していた

## 自動で落ちる（A 案。`ChallengeStyle.AUTO`、ID `auto-180-v1`。決定 65）

- 始める前の画面で「自分で落とす」（B 案）か「自動で落ちる」（A 案）を選ぶ。決まりが違うので、記録は決まりの ID で分け、一覧も選んだ方だけを出す
- 狙っている間も、形が 0.4 m/s で下がっていく（出てくる高さ（塔の上 1.3 m）から塔に着くまで 2〜3 秒）。下がっている間に ◀▶ と回転で合わせる
- 下げた位置で塔か台に重なるなら（当たり判定の角ばった形どうし。`StackWorld.overlaps`）、今の位置から物理で落とす。落ち始めの速さは、下がっていた速さのまま
- 塔や台に重なる位置・向きには、◀▶ と回転で動かせない（すり抜けて中に入らないように）
- 台の外を下がって、台の上面より 1 m 下まで行ったら、そこで落とす（落ちて数えられる）
- 「置く」を押すと、下がるのを待たずに、その場ですぐ落とす
- 時計・締切・揺れ待ち・崩れたあとの高さ・記録の保存は、自分で落とすと同じ。下がっている途中で 00:00 になった形は数えない（置く前の形と同じ）
- 上まで積み上がって出せなくなることは無い（出てくる高さは、いつも塔の上から決める）
- 落ちてくる高さは毎コマ変わるので、画面のフレーム（`ChallengeFrame`）には入れず、キャンバスの描画の中だけで読む（`ChallengeViewModel.ghostY`）

## 記録（`data/ChallengeRecords.kt`・`ChallengeStorage.kt`）

- 端末の中の `challenge_records.json`（AtomicFile）。外には何も送らない
- 結果が出たら ViewModel が保存する（画面を離れても保存は止めない）。run ID で 2 回保存しない。同じ決まりの記録だけを高い順に並べ、同じ高さは同じ順位（`rankOf`。「みんな」と同じ決め方）
- 読めないファイル（壊れている・決まりの ID が無い前の形式）は、上書きせずに `challenge_records.broken-<時刻>.json` に退避して空から始める
- 保存に失敗したら「再試行」できる。次の回にも進める（その回の記録は残らない、と出す）。開いたときの読み込みに失敗しても、新しい結果は保存しにいく
