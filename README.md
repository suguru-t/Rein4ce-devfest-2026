# ミチツミ（michitsumi）— デモ版

歩いた軌跡を積み木パーツに変えて、バランスを取りながらタワーを積む Android アプリ。
ハッカソン用の **「少し動くデモ版」** で、4 人で分担する前の共通基盤です。

- アプリ：Kotlin / Jetpack Compose（`app`）
- 共通ロジック：純 Kotlin（`core`）— パーツの形式、軌跡→パーツ変換、dyn4j 物理、サンプル、SVG
- サーバ：Ktor（`server`）— Cloud Run に載せる。タワーの保存・共有ページ・一覧

いまできること：

開くと、まず**ホーム**：まん中に、大きなアプリのアイコンの積み木の塔を載せた題字「ミチツミ」、「歩いた道を、積み上げよう」、コレクションと同じ「歩いた合計」のメーター（見本の本数は出さない）。その下に、記録・コレクション・積む・みんなの 4 つの行を画面の下まで広げて並べる（題字と同じ色の大きな積み木を 1 本の道でつなぎ、右に紙のカード）。押すと、その画面に移る（下のタブを押したときと同じ）。右上の歯車で設定が開く。下のタブバーはホームでは隠れていて、4 つの画面に入ると下から出てくる。4 つの画面で、タブバーの左の丸い家のボタンか端末の「戻る」を押すとホームに戻る（見ていた画面は続きから。記録の途中も止まらない）。記録中は、ホームの「記録」に「記録中」の札が出る。記録中に通知を押したときは、ホームにいても記録画面が出る（アプリを開き直したときは、ホームを飛ばして記録画面から始まる）

1. **記録**（旧：採集）：「デモ散歩」を再生するとサンプル軌跡が流れてパーツになる。同じメニューの「ファイル」で、実機で録った GPX / JSON も流せる。実機なら「記録開始」で GPS 記録（画面ロック中も続く）。歩きとジョギングだけがパーツになる（30 秒の窓で時速 14 km を超えると車・自転車とみなす。記録中は、超えた状態が 10 秒続いたら自動で記録を止めて、そこまでの分をパーツにする。1 点だけの GPS の飛びでは止めない。再生でも同じ）。パーツができると、AI（サーバの Gemini）が形・距離・日時から名前を付ける（届くまでは「名前を考え中…」。付かなければ「○ m の散歩」のまま）。見出しの画面名「みちのきろく」は押すと動く（ほかの画面の名前と同じ積み木。押したブロックが跳ねる。最後の「く」は画面の上のカメラの穴のあたりから落ちてきて収まる）。地図には、歩き始めた所に赤い旗、止めた所に青い旗（一周して近くで止めたら 2 本を左右に開く）、今いる場所に黄色の歩く人のピクトグラム（記録中は足を入れ替えて歩き、歩いている向きを向く。記録していないときはスマホの向いている方を向く）と、スマホの向いている方位を指すオレンジの三角（磁北と真北のずれを直す。デモ散歩の再生中は人だけ）。記録中は、見出しの歩いた長さの横の足跡が歩き続ける
2. **コレクション**（旧：手持ち）：同梱の見本 7 本（7 つの天気が 1 本ずつ。165 m の短い道から 1,631 m の長い道まで）＋記録したパーツ。見た目は「みんな」と同じポップな形（画面名の積み木、下に側面がのぞくブロックの札・カード・ボタン、太い丸ゴシック。拡大表示も同じ）。見出しの歩いた距離の合計は、開くたびにメーターのように 0 から上がる（「みんな」の見出しと同じ）。タップで拡大して名前を付ける（「AI に考えてもらう」で、AI の案を入れることもできる。Maps API キーがあれば、拡大した図の背景に歩いた場所の地図が出る。場所を残す前に採集したパーツは出ない）。拡大表示の「もう一度歩く」で、道を歩いた順に足跡がなぞる（スタートの赤い旗からゴールの青い旗へ。どのパーツも 6 秒で、時速 4.8 km で歩いたとして「約 ○ 倍速」と出る。「立ち止まる」で止める）。長押しで並べ替え中（ドラッグで並べ替え・× で削除）。道の色は歩いたときの天気で変わる（雨のなかまは青、雪は水色、くもり・霧は灰色、晴れはいつものオレンジ）。図の左上（北の反対側）に、天気のアイコン（太陽・雲・霧・雨・稲妻・雪の結晶）も出る。上の行で並び（いつもの順・新しい順・古い順・長い順・短い順）と天気の絞り込みを選べ、カードの右下の ☆ を押すとお気に入り（黄色の ★）になって「☆ お気に入り」で絞り込める（並びと絞り込みは、アプリを閉じても覚えている。長押しの並べ替えは「いつもの順」で絞り込んでいないときだけ）
3. **積む**：開くと、まず遊び方（モード）を選ぶ画面（ゲームのタイトル画面のように、台に積んだパーツの絵と画面名「みちをつむ」。下にモードの行：通常・3 分チャレンジ・毎日 1 つずつ積む。いま遊べるのは通常と 3 分チャレンジで、毎日 1 つずつ積むは「準備中」。通常と 3 分チャレンジのカードには、この端末での自分の最高の高さが出る）。選ぶとそのモードで遊び、上の「‹ 戻る」か端末の「戻る」で選ぶ画面に戻る（選ぶ画面での「戻る」はホームへ）。遊んでいる途中でほかの画面へ行って戻ったときは、続きから。通常：広い台（2.8 m）に、コレクションの全部のパーツ（見本は設定の「見本のパーツを出す」に合わせる）からランダムに 1 つずつ出てくる（同じパーツが何度出てもよい）。置いたら次が出て、終わりは無い。パーツが 1 つでも台から落ちたら終わりで、塔が落ち着くのを待って、そのときの高さを記録する（この端末での最高が、モードを選ぶ画面の通常のカードに出る。5 本まで積んでいたころの記録とは分けて数え直す）。上には「置いた ○ 個」。都合の悪い形が出たら「チェンジ」（模型の高さの右の ⇄ の積み木。右下に残りの回数）で、ほかのパーツにランダムに替えられる（1 ゲームに 3 回まで）。「やり直す」で、今のコレクションの全部のパーツではじめから。積むパーツを選ぶ機能はない（コレクションの「選択」と積む画面の「パーツを選ぶ」はやめた）。ドラッグか ◀▶（5 cm ずつ。長押しで続けて動く）で位置、15° 回転、「置く」で落下（「◀ ⟲ 15° 置く ⟳ 15° ▶」を 1 行に並べる）。塔全体が止まったら次へ（台から落ちたパーツは、落ちた時点で消えて数える）。終わったあと塔が止まらなかったとき（判定できない）と、1 個も残らなかったときは送信しない。終わりのカードの「サーバに送信」で「みんな」に送れる（同じパーツは 1 つにまとめ、配置は置いた数だけ送る）。長く歩いた道ほどパーツが大きい（パーツになる最短の 150 m で 0.7 倍、2 km 以上で 1.4 倍。上に「776 m の道 ・ 大きさ 1.1 倍」と出る）。歩いたときの天気で滑りやすさが変わる（晴れ → くもり → 霧 → 霧雨 → 雨 → 雪 の順に、パーツどうしで滑る。台の上では滑らない。霧雨・雨・雪は「雪の日の道 ・ とてもすべりやすい」のように知らせる）。狙っている間は大きさを変えず、塔が高くなったら、次のパーツが出てくる高さが入るところまでカメラが上がる（台は下に外れることがある）。終わったら、塔全体と台が入るように引いて見せる。高さは「模型の高さ」で、キャンバスの左端に台の上面を 0 にした目盛り（1 m ごとに「1m」の字、間が空けば 20 cm の細かい目盛り。「みんな」の断面図の標尺と同じ字）を重ねて描く。終わりのカードには「使った道：合計 1.23 km」（置いたパーツのうち（同じパーツは 1 回）、「記録開始」で歩いて記録した道だけの合計。見本・デモ散歩・ファイルのパーツと、出どころを残すようにする前に作ったパーツは数えない。見本・デモだけで積んだときは「見本・デモのパーツなので、歩いた距離は出ません」）。3 分チャレンジ：3 分間で、決まった 5 種類の形をどれだけ高く積めるか（台は下のほうで、縮尺は変えずに塔が高くなると視点が上がる。途中の揺れ待ちは 3 秒まで。崩れて低くなったら、次の形が出てくる高さと視点も下がる。「やり直す」「中断」がある。記録はこの端末の中だけ。詳しくは `docs/challenge-mode.md`）
4. **みんな**：サーバの `/towers` 一覧。見た目は題字「ミチツミ」の積み木に合わせたポップなブロック（太い丸ゴシック、アイコンの 4 色、下に濃い色がのぞく面。物差しごとの色は高い順がオレンジ、多い順が青緑、新しい順が紺）。最初の画面は**断面図**：物差し（高い順＝高さ、多い順＝パーツ数）ごとに、1 番のタワーと自分のいちばん良いタワーの 2 個を同じ縮尺で 1 本の台に並べ、左に標尺、いちばん高い記録に赤鉛筆の線。見出しは「あなたの最高 2.30 m ・ 最長まで あと 1.15 m」（多い順なら最多と本数）。自分が 1 番なら相手は 2 番。「ランキングを見る」で全部のタワーの一覧（紙片で 5 個ずつ、「前の 5 個」「次の 5 個」でめくる。絵はその一覧の中で同じ縮尺。1 番に「最長」「最多」の札）。「あなたのタワー」で自分が送ったタワーだけの一覧（番号はその中での順番。新しい順も選べる）。ニックネームを付けずに送ったタワーがあるときは「名前を付けると、次に送るタワーから名前が出ます」の一言が出て、押すとニックネームの窓が開く。タワーを押すと下から紙片が出て、「共有ページを開く」「リンクをコピー」。右上のリロードの印で取り直す。完成したタワーは「サーバに送信」で共有ページ URL が返る。自分が送ったタワーにはオレンジの「あなた」の札が出る。見分けるのは端末ごとの「持ち主の印」（端末の id に塩を付けてハッシュした 64 桁。`data/OwnerId`）で、送るタワーに入れ、一覧を取るときはヘッダ `X-Owner-Id` で送る。サーバは印を保存して「あなたのか」だけを答え、印そのものは誰にも返さない。アプリを入れ直しても同じ印なので札は残る（端末を替えると変わる。ログインは無い）。送信した id はスマホの中にも残すので、サーバが落ちていても札は出る。共有ページと LINE / X のプレビューには、設定のニックネームが「○○ さんが 5 個の散歩パーツで積みました」と出る
5. **背景の天気**：アプリ全体の方眼紙の上に、見ている画面に合わせた天気が出る（雨・雪・霧、くもりは流れる雲、晴れは天気アプリのような太陽。夜は太陽の代わりに月と星で、月はふだん三日月、満月の前後 1 日だけ満月。雨・くもりなどの夜は空の色が夜になる。スマホを傾けると太陽や月が少し動く）。ホーム・記録・積む・みんな・コレクションの一覧は今の天気で、コレクションでカードを押して大きく見ている間だけ、そのパーツを歩いたときの天気（拡大表示の窓の紙にも降る）。電池のため、描き直しはゆっくりな空で 1 秒に 30 回、雨・雪で 60 回まで。記録中は止まった絵にする
6. **設定**（ホームの右上の歯車）：見た目はコレクションの拡大表示と同じポップな枠（題字の積み木の 4 色の線を引いた見出し、まとまりごとの色の印と紙のカード、ブロックのスイッチ・選ぶ印・つまみ。ニックネームと「名前を付ける」の窓、使い方も同じ）。上から、みんなのタワー（ニックネーム。「AI に考えてもらう」で、集めた道の名前・本数・距離から AI が案を出す。歩いた場所（位置）は送らない）、システム（画面の明るさ（端末に合わせる・ライト・ダーク）、背景の天気の動き（出さない・止める・ふつう・なめらかの 4 段階のスライダー。選んでいる段階の説明が下に出る）、振動（押したときなどに端末を軽く振動させる。オフにすると振動しない）、BGM（全部の画面で同じ曲。オン・オフのスイッチと、曲（トコトコ（木琴）・ピコピコ（昔のゲーム機の音）・ウクレレ（ウクレレと口笛）の 3 曲を「‹ ›」で切り替える）、10 段階の音量のスライダー、初期設定に戻すボタン。ほかのアプリで音楽を流しているとき・アプリが裏に回ったときは流さない。曲は `tools/make_bgm.py` で作った曲で、`res/raw/bgm`・`bgm_chip`・`bgm_ukulele` を差し替えれば別の曲にできる）、効果音（ボタンを押したとき・題字や画面名の積み木を押したとき（左から音階を上がって、最後の積み木が上のド）・道を 1 本集めたときに鳴る木琴の音。オン・オフ。音は `tools/make_sfx.py` で作る））、記録中は画面を消さない、AI に名前を考えてもらう（オフなら何も送らない）、デモ（発表で使う。見本のパーツを出す・出さない、デモの天気：本当の天気の代わりに、晴れ・晴れの夜（三日月・満月）・くもり・霧・霧雨・雨・雷雨・雪を選ぶと、ホーム・記録・積む・みんな・コレクションの一覧の背景と、デモ散歩でできるパーツの天気がそれになる。発表が終わったら `data/AppSettings.kt` の `DEMO_SETTINGS` を false にすれば消える）、使い方、アプリについて（版・外に送るもの・使っている素材）。スマホの中だけに保存する。使い方は、開いたときにも出る（「次回から表示しない」にチェックを入れて閉じるまで）
7. **ダークモード**：野帳の色を夜の野帳（黒に近い緑の紙に明るい字）に切り替える。地図も暗い表示になる
8. **起動画面**（Android 12 以降）：積み木のアイコンと、すぐ下に題字「ミチツミ」。最後の「ミ」が右から落ちてきて 1 回はねて収まる。アプリを新しく開いたときは、続けてタイトルを出す：積み木の塔がうすく消え、題字「ミチツミ」が方眼の紙のまん中へ大きくなって「歩いた道を、積み上げよう」の一言が出て、1.5 秒ほどでホームの題字へ飛んで収まる（押さなくても進み、押せばすぐ飛ばせる。記録中に開いたとき・画面の作り直し・端末で動きを減らしているときは出さず、門の形の穴をくぐってホーム（記録中に開いたときは記録画面）に入る）。地の明るさは設定に合わせる（Android 13 以降）

## 動かし方

### Android アプリ

1. Android Studio（Narwhal 以降）で、このフォルダを開く
2. 地図のキーを、パソコンに 1 回だけ書く（下の「地図（Maps API キー）」を参照。書かなくても動く。無ければ地図の代わりに軌跡を Canvas 描画）
   - サーバの接続先は書かなくてよい（本番サーバ `https://road-collector-415368216017.asia-northeast1.run.app` につながる）。手元のサーバにつなぐときだけ、Studio が作る `local.properties` に `SERVER_BASE_URL` を書く（`local.properties.example` と下の「サーバの接続先」を参照）
3. Run。エミュレータでも実機でも可（minSdk 26）

**発表・実機テストは release ビルドで**：debug ビルドは Compose が遅く、エミュレータで起動が約 4.5 秒かかる（release なら約 2 秒）。release もチーム共通の鍵で署名するので、地図もそのまま出て、debug ビルドの上に入れ替えられる。

- Android Studio：左下の Build Variants で `app` を `release` にして Run
- コマンド：`./gradlew :app:assembleRelease` → `app/build/outputs/apk/release/app-release.apk` を `adb install -r` で入れる
- release ではブレークポイントで止めて調べることができない（Logcat のログは出る）。不具合を調べるときは debug に戻す
- この鍵（`app/debug.keystore`）はリポジトリに入っていて誰でも使えるので、作った APK は**チームの外には配らない**（配ると、他の人も同じ鍵で「更新版」を作れてしまう）

### 地図（Maps API キー）

記録画面の地図は Google Maps で、`MAPS_API_KEY` が無いと軌跡だけを Canvas に描く。キーは A が管理している 1 つをチームで共有する（Slack で A から受け取る。**リポジトリには入れない**）。

**キーはパソコンに 1 回だけ書く**：パソコンのユーザーの Gradle の設定ファイルに 1 行足すと、そのパソコンのどのクローン・作業フォルダ（`git worktree`）でも読まれる。クローンし直しても書き直さなくてよい。

- ファイル：Windows は `C:\Users\<ユーザー名>\.gradle\gradle.properties`、Mac / Linux は `~/.gradle/gradle.properties`（無ければ作る）
- 書く行：`MAPS_API_KEY=AIza…`（Slack で受け取ったキー）
- Android Studio で開いているなら、書いたあとに Sync（「Sync Project with Gradle Files」）する
- **リポジトリの中の `gradle.properties`（このフォルダのいちばん上にある、同じ名前のファイル）には書かない**。そちらは git に入るので、書くとキーが公開されてしまう（うっかり書いても、ビルドはそこからキーを読まないようにしてある）

読む順は、このクローンの `local.properties` → コマンドの `-PMAPS_API_KEY=…` → `~/.gradle/gradle.properties` → 環境変数 `MAPS_API_KEY`（GitHub Actions は Secrets から渡す）。前と同じく `local.properties` に書いてもよい（そちらが先に読まれる）。空の `MAPS_API_KEY=` の行は、無いのと同じに扱う。`~/.gradle/gradle.properties` はリポジトリの外にあるので、git に入ることはない。

`local.properties` には SDK の場所（`sdk.dir`）も入っている。Android Studio で開けば作ってくれるが、`local.properties` の無い作業フォルダ（`git worktree`）をコマンドでビルドすると「SDK location not found」で止まることがある。そのときは、環境変数 `ANDROID_HOME` に SDK の場所を 1 回設定しておく（Windows は `%LOCALAPPDATA%\Android\Sdk`、Mac は `~/Library/Android/sdk`。Windows はシステムの環境変数、Mac は `~/.zshrc` などに書く）。

- デバッグ署名はチーム共通の鍵 `app/debug.keystore`（パスワードは Android 標準と同じ `android`）。全員と GitHub Actions のビルドが同じ署名になるので、キーの「Android アプリ」制限にはこの鍵の SHA-1 だけ登録してある。自分の PC で作った鍵は使わない
- 同じ署名なので、手元のビルドと Actions の APK を同じ端末に入れ替えてもアンインストールは要らない
- **共通の鍵になる前のビルド（2026-11-06 以前）が入っている端末・エミュレータは、最初の 1 回だけアンインストールしてから入れる**（署名が変わるため）。アンインストールするとコレクション（集めたパーツ）も消えるので、残したいものがあれば先にタワーをサーバに送るなどしておく
- キーは「API の制限」で Maps SDK for Android だけに絞ってある（リポジトリが公開で、Actions の APK からキーを取り出せるため。地図の表示は課金されない）
- 鍵を作り直したときは、Google Cloud Console のキーの制限に新しい SHA-1 を登録し直す（`keytool -list -v -keystore app/debug.keystore -storepass android` で出る）

実機で GPS を試すときは、権限ダイアログで「アプリの使用中のみ許可」でよい（バックグラウンド権限は使わない）。
エミュレータで歩くには Extended Controls → Location で GPX を再生するか、アプリ内の「デモ散歩」を使う。

「デモ散歩」メニューの「実機で録ったもの」の「ファイル」で、実機で録った軌跡ファイル（GPX / JSON）を早回しで流せる（`core/io/TrackFileParser`）。
GPX は `<trkpt lat lon><time>` を読む（精度は不明として扱う）。JSON は `TrackPoint` の配列（`[{"lat":…,"lng":…,"accuracyM":…,"timeMs":…}]`）か、`points` を持つオブジェクト（`{"points":[…]}`。`Track` 全体でも可）。
デモ散歩・ファイル再生とも、時刻は「最後の点 = 今」にずらして流すので、パーツの採集日時は再生した日時になる。

## データ形式（ここだけは全員で守る）

```kotlin
data class Part(
    val id: String,
    val points: List<Pt>,     // 正規化済み。バウンディングボックス中心が原点、長辺 1.0、y 上向き。最大 24 個
    val thickness: Float,     // 太さ（長辺に対する比率、初期値 0.15）
    val closed: Boolean,      // 輪なら true
    val kind: Kind,           // BAR / L / U / RING / ZIGZAG / OTHER（表示用）
    val distanceM: Int,
    val walkedAt: Long,
    val name: String? = null, // Gemini 命名（任意）
)
```

生の GPS 点列（`TrackPoint`）は `Part` に入れない。サーバにも送らない。

パーツを歩いた場所（形の中心の緯度・経度と長辺の長さ、歩き始めた時刻。`PartPlace`）も `Part` には入れない。コレクションの拡大表示の背景に地図を敷くためだけに、スマホの中の別のファイル（`parts_places.json`）に持つ。`Part` はタワーと一緒にサーバへ送られて共有ページに出るので、入れると歩いた場所が分かってしまうため。

パーツを歩いたときの天気（`WalkWeather`。世界気象機関の天気コードと降水量）も、`Part` には入れずスマホの中（`parts_weather.json`）に持つ（共通のデータ形式を変えないため）。天気は採集のあとに Open-Meteo（キー不要・無料）から取る。取るのは歩き始めた時刻の天気（長く歩いて途中で天気が変わっても、歩き始めたときの天気。1 時間ごとの天気なので、歩き始めた時台が今と同じなら今の天気、前の時台ならその時台の天気。歩き始めた時刻を持つ前に採集したパーツは、歩き終えた時刻の天気）。送る位置は 0.1 度（約 10 km）に丸めて、歩いた正確な場所は外に出さない。電波が無くて取れなかったパーツは、次にアプリを開いたときに聞き直す（90 日前まで）。天気データは [Open-Meteo.com](https://open-meteo.com/)（CC BY 4.0）。アプリでも、コレクションの拡大表示で天気を出すところに出どころを添えている（`ui/weather/WeatherCredit.kt`）。

## 設定・権限の要点

セキュリティとプライバシーの対策（していること・していないこと・聞かれそうな質問）は `docs/security.md` にまとめてある。

- Android 14 以降：`FOREGROUND_SERVICE_LOCATION` 権限と `foregroundServiceType="location"` が必須（設定済み）
- `ACCESS_BACKGROUND_LOCATION` は使わない。記録は必ずアプリを開いた状態のボタンから開始する
- 暗号化しない通信（http）は debug ビルドだけ許す（ローカルサーバ http://10.0.2.2 用。`src/debug/res/xml/network_security_config.xml`）。release ビルドは https だけなので、ローカルサーバにつなぐときは debug ビルドで動かす
- `local.properties` は git に入れない（API キー）
