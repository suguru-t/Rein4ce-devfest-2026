# ミチツミ（michitsumi）— デモ版

歩いた軌跡を積み木パーツに変えて、バランスを取りながらタワーを積む Android アプリ。
ハッカソン用の **「少し動くデモ版」** で、4 人で分担する前の共通基盤です。

- アプリ：Kotlin / Jetpack Compose（`app`）
- 共通ロジック：純 Kotlin（`core`）— パーツの形式、軌跡→パーツ変換、dyn4j 物理、サンプル、SVG
- サーバ：Ktor（`server`）— Cloud Run に載せる。タワーの保存・共有ページ・一覧

いまできること：

1. **記録**（旧：採集）：「デモ散歩」を再生するとサンプル軌跡が流れてパーツになる。同じメニューの「ファイル」で、実機で録った GPX / JSON も流せる。実機なら「記録開始」で GPS 記録（画面ロック中も続く）。歩きとジョギングだけがパーツになる（30 秒の窓で時速 14 km を超えると車・自転車とみなす。記録中は、超えた状態が 10 秒続いたら自動で記録を止めて、そこまでの分をパーツにする。1 点だけの GPS の飛びでは止めない。再生でも同じ）。パーツができると、AI（サーバの Gemini）が形・距離・日時から名前を付ける（届くまでは「名前を考え中…」。付かなければ「○ m の散歩」のまま）。見出しの題字「ミチツミ」は押すと動く（押したブロックが跳ねる。最後の「ミ」は画面の上のカメラの穴のあたりから落ちてきて収まる）
2. **コレクション**（旧：手持ち）：同梱の見本 7 本（7 つの天気が 1 本ずつ。165 m の短い道から 1,631 m の長い道まで）＋記録したパーツ。見た目は「みんな」と同じポップな形（画面名の積み木、下に側面がのぞくブロックの札・カード・ボタン、太い丸ゴシック。拡大表示と、積む画面の「パーツを選ぶ」の窓も同じ）。見出しの歩いた距離の合計は、開くたびにメーターのように 0 から上がる（「みんな」の見出しと同じ）。右上の「選択」で最大 5 本選んで「積む」（「ランダムに選ぶ」で、1〜5 本をおまかせで選ぶこともできる。見本も選ぶ対象）。タップで拡大して名前を付ける（「AI に考えてもらう」で、AI の案を入れることもできる。Maps API キーがあれば、拡大した図の背景に歩いた場所の地図が出る。場所を残す前に採集したパーツは出ない）。長押しで並べ替え中（ドラッグで並べ替え・× で削除）。道の色は歩いたときの天気で変わる（雨のなかまは青、雪は水色、くもり・霧は灰色、晴れはいつものオレンジ）。図の左上（北の反対側）に、天気のアイコン（太陽・雲・霧・雨・稲妻・雪の結晶）も出る。上の行で並び（いつもの順・新しい順・古い順・長い順・短い順）と天気の絞り込みを選べ、カードの右下の ☆ を押すとお気に入り（黄色の ★）になって「☆ お気に入り」で絞り込める（並びと絞り込みは、積む画面の「パーツを選ぶ」の窓と共通で、アプリを閉じても覚えている。長押しの並べ替えは「いつもの順」で絞り込んでいないときだけ）
3. **積む**：ドラッグで位置、15° 回転、「置く」で落下。塔全体が止まったら次へ（台から落ちたパーツは、落ちた時点で消えて数える）。5 個置き切って塔が止まったら高さ確定。止まらなかったとき（判定できない）と、1 個も残らなかったときは送信しない。積む画面の「パーツを選ぶ」（完成のあとは「パーツを選び直す」）で、コレクションに戻らずに積むパーツを選び直せる（下から出る窓に、コレクションと同じ並びの小さなカード。5 本まで）。選ばずに開いたときは、コレクションの上から 5 本で始まる。長く歩いた道ほどパーツが大きい（パーツになる最短の 150 m で 0.7 倍、2 km 以上で 1.4 倍。上に「776 m 歩いた道 ・ 大きさ 1.1 倍」と出る）。歩いたときの天気で滑りやすさが変わる（晴れ → くもり → 霧 → 霧雨 → 雨 → 雪 の順に、パーツどうしで滑る。台の上では滑らない。霧雨・雨・雪は「雪の日の道 ・ とてもすべりやすい」のように知らせる）。狙っている間は大きさを変えず、塔が高くなったら、次のパーツが出てくる高さが入るところまでカメラが上がる（台は下に外れることがある）。置き切ったら、塔全体と台が入るように引いて見せる
4. **みんな**：サーバの `/towers` 一覧。見た目は題字「ミチツミ」の積み木に合わせたポップなブロック（太い丸ゴシック、アイコンの 4 色、下に濃い色がのぞく面。物差しごとの色は高い順がオレンジ、多い順が青緑、新しい順が紺）。最初の画面は**断面図**：物差し（高い順＝高さ、多い順＝パーツ数）ごとに、1 番のタワーと自分のいちばん良いタワーの 2 個を同じ縮尺で 1 本の台に並べ、左に標尺、いちばん高い記録に赤鉛筆の線。見出しは「あなたの最高 2.30 m ・ 最長まで あと 1.15 m」（多い順なら最多と本数）。自分が 1 番なら相手は 2 番。「ランキングを見る」で全部のタワーの一覧（紙片で 5 個ずつ、「前の 5 個」「次の 5 個」でめくる。絵はその一覧の中で同じ縮尺。1 番に「最長」「最多」の札）。「あなたのタワー」で自分が送ったタワーだけの一覧（番号はその中での順番。新しい順も選べる）。ニックネームを付けずに送ったタワーがあるときは「名前を付けると、次に送るタワーから名前が出ます」の一言が出て、押すとニックネームの窓が開く。タワーを押すと下から紙片が出て、「共有ページを開く」「リンクをコピー」。右上のリロードの印で取り直す。完成したタワーは「サーバに送信」で共有ページ URL が返る。自分が送ったタワーにはオレンジの「あなた」の札が出る。見分けるのは端末ごとの「持ち主の印」（端末の id に塩を付けてハッシュした 64 桁。`data/OwnerId`）で、送るタワーに入れ、一覧を取るときはヘッダ `X-Owner-Id` で送る。サーバは印を保存して「あなたのか」だけを答え、印そのものは誰にも返さない。アプリを入れ直しても同じ印なので札は残る（端末を替えると変わる。ログインは無い）。送信した id はスマホの中にも残すので、サーバが落ちていても札は出る。共有ページと LINE / X のプレビューには、設定のニックネームが「○○ さんが 5 個の散歩パーツで積みました」と出る
5. **背景の天気**：アプリ全体の方眼紙の上に、見ている画面に合わせた天気が出る（雨・雪・霧、くもりは流れる雲、晴れは天気アプリのような太陽。夜は太陽の代わりに月と星で、月はふだん三日月、満月の前後 1 日だけ満月。雨・くもりなどの夜は空の色が夜になる。スマホを傾けると太陽や月が少し動く）。記録・みんな・コレクションの一覧は今の天気で、コレクションでカードを押して大きく見ている間だけ、そのパーツを歩いたときの天気（拡大表示の窓の紙にも降る）。積むでは降らない。電池のため、描き直しはゆっくりな空で 1 秒に 30 回、雨・雪で 60 回まで。記録中は止まった絵にする
6. **設定**（記録画面の右上の歯車）：上から、みんなのタワー（ニックネーム。「AI に考えてもらう」で、集めた道の名前・本数・距離から AI が案を出す。歩いた場所（位置）は送らない）、システム（画面の明るさ（端末に合わせる・ライト・ダーク）、背景の天気の動き（出さない・止める・ふつう・なめらかの 4 段階のスライダー。選んでいる段階の説明が下に出る）、振動（押したときなどに端末を軽く振動させる。オフにすると振動しない）、BGM（全部の画面で同じ曲。オン・オフのスイッチと、曲（トコトコ（木琴）・ピコピコ（昔のゲーム機の音）・ウクレレ（ウクレレと口笛）の 3 曲を「‹ ›」で切り替える）、10 段階の音量のスライダー、初期設定に戻すボタン。ほかのアプリで音楽を流しているとき・アプリが裏に回ったときは流さない。曲は `tools/make_bgm.py` で作った曲で、`res/raw/bgm`・`bgm_chip`・`bgm_ukulele` を差し替えれば別の曲にできる）、効果音（ボタンを押したとき・題字や画面名の積み木を押したとき（左から音階を上がって、最後の積み木が上のド）・道を 1 本集めたときに鳴る木琴の音。オン・オフ。音は `tools/make_sfx.py` で作る））、記録中は画面を消さない、AI に名前を考えてもらう（オフなら何も送らない）、デモ（発表で使う。見本のパーツを出す・出さない、デモの天気：本当の天気の代わりに、晴れ・晴れの夜（三日月・満月）・くもり・霧・霧雨・雨・雷雨・雪を選ぶと、記録・みんな・コレクションの一覧の背景と、デモ散歩でできるパーツの天気がそれになる。発表が終わったら `data/AppSettings.kt` の `DEMO_SETTINGS` を false にすれば消える）、使い方、アプリについて（版・外に送るもの・使っている素材）。スマホの中だけに保存する。使い方は、開いたときにも出る（「次回から表示しない」にチェックを入れて閉じるまで）
7. **ダークモード**：野帳の色を夜の野帳（黒に近い緑の紙に明るい字）に切り替える。地図も暗い表示になる
8. **起動画面**（Android 12 以降）：積み木のアイコンと、すぐ下に題字「ミチツミ」。最後の「ミ」が右から落ちてきて 1 回はねて収まる。アプリを新しく開いたときは、続けてタイトルを出す：積み木の塔がうすく消え、題字「ミチツミ」が方眼の紙のまん中へ大きくなって「歩いた道を、積み上げよう」の一言が出て、1.5 秒ほどで記録画面の見出しへ飛んで収まる（押さなくても進み、押せばすぐ飛ばせる。記録中に開いたとき・画面の作り直し・端末で動きを減らしているときは出さず、門の形の穴をくぐって記録画面に入る）。地の明るさは設定に合わせる（Android 13 以降）

## 動かし方

### Android アプリ

1. Android Studio（Narwhal 以降）で、このフォルダを開く
2. Studio が作る `local.properties` に `local.properties.example` の 2 行を足す
   - `MAPS_API_KEY=`（空でも動く。空なら地図の代わりに軌跡を Canvas 描画。下の「地図（Maps API キー）」を参照）
   - `SERVER_BASE_URL=https://road-collector-415368216017.asia-northeast1.run.app`（本番サーバ。下の「サーバの接続先」を参照）
3. Run。エミュレータでも実機でも可（minSdk 26）

**発表・実機テストは release ビルドで**：debug ビルドは Compose が遅く、エミュレータで起動が約 4.5 秒かかる（release なら約 2 秒）。release もチーム共通の鍵で署名するので、地図もそのまま出て、debug ビルドの上に入れ替えられる。

- Android Studio：左下の Build Variants で `app` を `release` にして Run
- コマンド：`./gradlew :app:assembleRelease` → `app/build/outputs/apk/release/app-release.apk` を `adb install -r` で入れる
- release ではブレークポイントで止めて調べることができない（Logcat のログは出る）。不具合を調べるときは debug に戻す
- この鍵（`app/debug.keystore`）はリポジトリに入っていて誰でも使えるので、作った APK は**チームの外には配らない**（配ると、他の人も同じ鍵で「更新版」を作れてしまう）

### 地図（Maps API キー）

記録画面の地図は Google Maps で、`MAPS_API_KEY` が無いと軌跡だけを Canvas に描く。キーは A が管理している 1 つをチームで共有する（Slack で A から受け取って `local.properties` に書く。**リポジトリには入れない**）。

- デバッグ署名はチーム共通の鍵 `app/debug.keystore`（パスワードは Android 標準と同じ `android`）。全員と GitHub Actions のビルドが同じ署名になるので、キーの「Android アプリ」制限にはこの鍵の SHA-1 だけ登録してある。自分の PC で作った鍵は使わない
- 同じ署名なので、手元のビルドと Actions の APK を同じ端末に入れ替えてもアンインストールは要らない
- **共通の鍵になる前のビルド（2026-11-06 以前）が入っている端末・エミュレータは、最初の 1 回だけアンインストールしてから入れる**（署名が変わるため）。アンインストールするとコレクション（集めたパーツ）も消えるので、残したいものがあれば先にタワーをサーバに送るなどしておく
- キーは「API の制限」で Maps SDK for Android だけに絞ってある（リポジトリが公開で、Actions の APK からキーを取り出せるため。地図の表示は課金されない）
- 鍵を作り直したときは、Google Cloud Console のキーの制限に新しい SHA-1 を登録し直す（`keytool -list -v -keystore app/debug.keystore -storepass android` で出る）

実機で GPS を試すときは、権限ダイアログで「アプリの使用中のみ許可」でよい（バックグラウンド権限は使わない）。
エミュレータで歩くには Extended Controls → Location で GPX を再生するか、アプリ内の「デモ散歩」を使う。

「デモ散歩」メニューの「実機で録ったもの」の「ファイル」で、実機で録った軌跡ファイル（GPX / JSON）を早回しで流せる（`core/io/TrackFileParser`）。
GPX は `<trkpt lat lon><time>` を読む（精度は不明として扱う）。JSON は `TrackPoint` の配列（`[{"lat":…,"lng":…,"accuracyM":…,"timeMs":…}]`）か、`points` を持つオブジェクト（`{"points":[…]}`。`Track` 全体でも可）。
デモ散歩・ファイル再生とも、時刻は「最後の点 = 今」にずらして流すので、パーツの採集日時は再生した日時になる。

### サーバの接続先

本番サーバ（Cloud Run）：https://road-collector-415368216017.asia-northeast1.run.app

アプリは既定でこの URL につながる。ローカルで `./gradlew :server:run` するときだけ、`local.properties` に `SERVER_BASE_URL=http://10.0.2.2:8080` を書く（10.0.2.2 はエミュレータから見たホスト PC の localhost）。
この値はビルド時にアプリへ埋め込まれるので、書き換えたら Gradle Sync してから Run し直す。

### サーバ（ローカル）

```
./gradlew :server:run
# → http://localhost:8080/   http://localhost:8080/towers
```

Cloud Run へのデプロイは [server/README.md](server/README.md)。

### テスト

```
./gradlew :core:test     # 変換ロジック・物理・SVG・軌跡ファイル読み込み
./gradlew :server:test   # サーバの API（保存・一覧・共有ページ・画像）
./gradlew :app:testDebugUnitTest   # アプリの手持ちの保存（Android なしで動く）
```

`core` は Android に依存しないので、変換ロジックと物理はここで素早く検証できる。

### 自動チェック（GitHub Actions）

main への push とプルリクエストのたびに、`core`・`server`・`app` のテスト、`server` のビルド、`app` の APK ビルドが自動で走る（`.github/workflows/ci.yml`）。結果はリポジトリの Actions タブで見られる。

ビルドした APK は、各実行結果ページの Artifacts にある `app-debug.apk` からダウンロードできる（GitHub へのログインが必要。14 日間保存）。

- この APK は本番サーバにつながる。リポジトリの Secrets に `MAPS_API_KEY` が入っていれば地図も出る（無ければ軌跡を Canvas で描く）
- 署名はチーム共通の `app/debug.keystore` なので、手元でビルドしたアプリが入っている端末にもそのまま上書きで入る

### 各担当の「次にやること」

- **A（採集）**：Android 実機で歩いて `ConversionParams` の数値（最低 150 m、精度 30 m、最小移動 5 m、最大速度 5 m/s、歩き・ジョギングの上限 3.9 m/s（時速 14 km。30 秒の窓の直線距離で測る。記録中に超えた状態が 10 秒続いたら自動で止めて、そこまでをパーツにする）、ε 10 m（GPS が粗いときは精度に合わせて大きくする）、頂点 24 個）を確認。特に Android の精度値で ε がどこまで上がるか（画面には出さず、Logcat の `CollectViewModel` に出る）。Maps API キーを入れて地図表示を確認（GPX / JSON の読み込みと、iPhone の GPX 6 本での調整は済み。Issue #1）
- **B（変換・手持ち）**：`TrackToPart.classify` の精度（実データで棒/L/U/輪/ジグザグがどう出るか）。手持ち画面の見た目、削除、並び替え
- **C（サーバ）**：`TowerStore` の Firestore 版を Cloud Run にデプロイして確認。`og:image` を PNG に。`POST /parts/name`（Vertex AI / Gemini）。対戦方式が決まれば `/challenges`
- **D（ゲーム）**：操作感（ドラッグ感度、回転の刻み）、台の幅、摩擦などの調整。静止判定の待ち時間。対戦モード（交互置き or 非同期スコアバトル）

## データ形式（ここだけは全員で守る）

```kotlin
data class Part(
    val id: String,
    val points: List<Pt>,     // 正規化済み。バウンディングボックス中心が原点、長辺 1.0、y 上向き。最大 24 個
    val thickness: Float,     // 太さ（長辺に対する比率、初期値 0.15）
    val closed: Boolean,      // 輪なら true
    val kind: Kind,           // BAR / L / U / RING / ZIGZAG / OTHER（表示用）
    val distanceM: Int,
    val walkedAt: Long,
    val name: String? = null, // Gemini 命名（任意）
)
```

生の GPS 点列（`TrackPoint`）は `Part` に入れない。サーバにも送らない。

パーツを歩いた場所（形の中心の緯度・経度と長辺の長さ。`PartPlace`）も `Part` には入れない。コレクションの拡大表示の背景に地図を敷くためだけに、スマホの中の別のファイル（`parts_places.json`）に持つ。`Part` はタワーと一緒にサーバへ送られて共有ページに出るので、入れると歩いた場所が分かってしまうため。

パーツを歩いたときの天気（`WalkWeather`。世界気象機関の天気コードと降水量）も、`Part` には入れずスマホの中（`parts_weather.json`）に持つ（共通のデータ形式を変えないため）。天気は採集のあとに Open-Meteo（キー不要・無料）から取る。送る位置は 0.1 度（約 10 km）に丸めて、歩いた正確な場所は外に出さない。電波が無くて取れなかったパーツは、次にアプリを開いたときに聞き直す（90 日前まで）。天気データは [Open-Meteo.com](https://open-meteo.com/)（CC BY 4.0）。アプリでも、コレクションの拡大表示で天気を出すところに出どころを添えている（`ui/weather/WeatherCredit.kt`）。

## 設定・権限の要点

- Android 14 以降：`FOREGROUND_SERVICE_LOCATION` 権限と `foregroundServiceType="location"` が必須（設定済み）
- `ACCESS_BACKGROUND_LOCATION` は使わない。記録は必ずアプリを開いた状態のボタンから開始する
- `usesCleartextTraffic="true"` はローカルサーバ（http://10.0.2.2）用。Cloud Run（https）だけになったら外してよい
- `local.properties` は git に入れない（API キー）
